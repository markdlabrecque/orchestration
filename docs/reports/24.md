# Ticket 24: bounded transcript reads and append-only retries

## What changed

Transcript model lookup now scans backward in 65,536-byte binary chunks, assembles split records, and decodes UTF-8 with replacement. It accepts valid final JSON without a newline and selects a non-synthetic string model with only that record's nonempty top-level string effort. Within a single `subagent_report` call, retries read appended bytes only and preserve an incomplete final record; shrink or inode replacement resets the scan. No bookkeeping, policy, event, or run-pairing behavior changed.

## Test evidence

- Red-first coverage: the initial focused suite had 7 expected failures (75 tests); six exposed full-prefix/repeated reads and one exposed acceptance of a numeric model. Semantic tests for long/split UTF-8 records, replacement decoding, and unterminated valid JSON passed.

- Earlier green runs before the latest integration/rebase had 77 focused tests (79.478s) and 391 full tests (307.880s), plus the Pi Node suite (10 passed). Latest results above supersede these counts.
- Measured fixture/read evidence (65,536-byte actual chunk size): 1,400,170-byte EOF-local fixture read 65,536 bytes in 1 call (131,072 permitted); 1,400,169-byte older-model fixture read 1,400,169 bytes in 22 calls; 600,296-byte long multibyte unterminated record read 600,296 bytes in 10 calls. Unchanged retries read a 1,400,000-byte fixture once per report call (22 calls each); append and partial-completion cases read 1,400,171 and 1,400,172 bytes respectively in 23 calls, without rereading the prefix. Shrink read 1,400,172 bytes total (23 calls); inode replacement read 2,800,172 bytes total (44 calls). Per-call requests were no larger than 65,536 bytes.
