# Ticket 20: Opt-in checkout relocation

## What changed

Added explicit `--relocate-checkout` consent for moving a root checkout's contents into `code/main` while retaining the outer directory and orchestration state. `--force` remains limited to overwriting `.orch`. Preflight refuses conflicts and unsafe Git layouts before mutation; the round-one fix also refuses all internal Git metadata symlinks (including dangling symlinks), without following them. Documentation now describes both starting layouts and requires confirmation before running the mutating script. Relocation was exercised only in temporary fixtures; no real checkout was moved.

## Test evidence

- `python3 -m unittest discover -s tests -v`: 358 tests passed; 15 existing skips.
- Shell suites: setup-project 30 passed; setup-worktree-agent 184 passed; reap-worktrees 55 passed; retire-worktree 125 passed.
- `git diff --check` passed.

Bash 3.2 was unavailable for a runtime check. The implementation uses constructs compatible with Bash 3.2; runtime verification on that version remains outstanding.

## Review and follow-ups

Round 1 bounced the change after identifying that a relative `.git` symlink into an external object store could invalidate the checkout during relocation. The fix conservatively refuses all internal Git metadata symlinks before mutation. Round 2 approved with no findings. No follow-ups were deferred.

The project instructions waive separate verification, browser, and accessibility checks; these were not run, and no verifier errors were reported. PR/merge remains pending the orchestrator. This report does not claim a merge or commit.
