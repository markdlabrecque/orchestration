# Ticket 108 report: Narrow review after round 1 to open must-fix findings

Issue: https://github.com/markdlabrecque/orchestration/issues/108

## Result

From review round 2 on, the reviewer re-checks only the open must-fix findings (by ledger id) and the code changed to fix them. A new finding in round 2+ can be must-fix only in one of four categories: `correctness`, `security`, `test`, `fix-defect`.

`orch finding add` gains `--category`. In round 2+, a must-fix without a category is stored as a follow-up with a fixed reason, and the text output shows the downgrade. The `findings` table gains nullable `category` and `reason` columns, with a migration for existing DBs. `orch phase <ticket> fix` from `review` is refused with exit 3 when the ticket is in round 2+, has ledger rows, and has no open must-fix finding. The gate does not apply to `verify -> fix`, `ci -> fix`, round 1, or tickets without ledger rows.

Docs were updated in `agents/reviewer.md`, `skills/orchestration/references/ticket-pipeline.md` ("Review findings ledger"), and `skills/orchestration/references/orch-cli.md`.

Changes are uncommitted in the worktree at `/Users/mark/Projects/orchestration/code/108`, per instruction.
