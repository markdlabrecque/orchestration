Baseline confirmation requires explicit reproduction evidence, registered tickets and a verified base SHA. Durable SQLite records and append-only events expose confirmation, gate waits, resolution and refresh outcomes. The scheduler prioritizes a ready fixing ticket without blocking affected implementation or unrelated work. Only the affected full-suite gate waits, and the owner does not wait on itself.

Resolution requires a merged/done owner and an explicit fixing SHA reachable from the configured local base. The CI candidate is not assumed to be the squash commit. Main records idempotent refresh requests for stale affected worktrees, including fixes already merged at confirmation; it never rebases those worktrees itself.

Ticket-local refresh requires an explicit serial stage boundary. Guards reject dirty tracked, staged or untracked work, Git operations in progress, incorrect linked-worktree identity or branch, and active/unknown pending runs. A durable reservation excludes dispatch, launch, retirement and merge during refresh. Rebase uses a checked base containing the fix, without autostash, automatic conflict resolution or destructive abort. Conflicts and interrupted reservations persist for explicit recovery. Phase and repair budgets stay intact.

Revision changes invalidate prior evidence without deleting history. Fresh tests and independent review require acknowledgment bound to current HEAD; that acknowledgment expires when HEAD changes. Exact-head merge enforcement remains separate and intact.

## Completion evidence and guard limits

Pending runs stay active/unknown until existing complete SubagentStop evidence or exact-run `complete-run` attestation establishes completion. The ticket orchestrator must establish invocation return and stopped child work before attesting. Session health is not completion evidence, and completing one run does not clear another. Completion does not replace model resolution, classification or routing.

These guards are a cooperative protocol, not a filesystem sandbox. Evidence text and external test/review attestations cannot be authenticated. Detached or unrecorded writers, external terminals and hooks can bypass reservations; ignored or external assets are not protected. The orchestrator must exclude those writers during refresh/recovery, preserve ignored assets separately and leave unknown runs pending. Known child rejection is not an authentication boundary. Legacy branches without recorded identity require separately authorized reconciliation. Resolution checks local reachability, not remote tracker truth or a fetch.
